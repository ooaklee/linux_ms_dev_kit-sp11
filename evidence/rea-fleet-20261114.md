## REA-1 — qcpmic8380.sys (PMIC)
- SPMI register-level driver: `\Device\Spmi\SUPERUSER`, PON/reset-reason
  logging (PON_REASON1, WARM/SOFT_RESET_REASON, POFF_REASON), staged
  watchdog S1/S2, PS_HOLD/SW_RESET control. ACPI QCOM0C2B / QCOM0CD3.
- **No glink/rpmsg/servreg machinery at all** (no strings, no imports).
  Windows' glink users live in other payloads (qcpds/qcsubsys-class).
- Conclusion: Linux pmic_glink (+ #83/#84 generation/ACK attribution)
  has no counterpart gap vs this binary.
- Possible follow-up: SPMI PON reset-reason logging driver for Linux
  (power/nvmem class) — nice-to-have diagnostics parity.

## REA-6 — battery + powermeter
- SurfaceBattery.sys: dual-transport ACPI (`MSHW0146`) **and** SAM-over-SSH
  battery miniclass (BIX/BST/PSR/BTP/BPM methods). No SMBus gauge access —
  EC/SAM owns the gauge.
- SurfacePowerMeterDriver.sys: four meter backends — MAX34407 (I2C),
  **MAX34417 (I2C, EMI v2)**, SAM/HID channel, virtual. 10 ms/8 Hz sampling,
  15 min/35 h overflow windows.
- DTS cross-check: five MAX34417 instances on i2c4 (0x12/0x14/0x16/0x18/0x1a)
  already noted in x1p42100-microsoft-sp12in.dts.
- **Gaps:** (1) no MSHW0146 ACPI battery driver in-tree; (2) no MAX34417
  driver (only max34408 sibling in drivers/iio/adc); (3) SAM power-meter
  HID channel undocumented.

## REA-2 — surfacecamfrontsensor8380.sys (front camera)
- Front sensor modules: ov02c10 (OVTI02C1) / imx681 (SONY0681); FFC variants.
- Power-on order (CAMF_RES_MSHW0490.bin): rail_mmcx → xo/ahb/gdsc/cpas clocks
  → cam_cc_titan_top_gdsc → reset GPIO → mclk4 → LDO3_M + LDO7_B → delays;
  **power-off blob is the exact mirror reverse — full teardown, no retention**.
- Stream-off returns sensor to *idle* (power retained) — matches #89
  retained-stop. Failed *PowerOn* unwinds all acquired resources in reverse
  (power released). Failed stream-on after power-up retains power → idle.
- No cross-sensor borrowing: front driver never touches vd55g1/ov13858 rails;
  only refcounted SoC votes (RPMH arc client) are shared.
- Action items: verify #89 stream-on-failure branch retains power/idle and
  probe-failure branch does full reverse teardown; build GPIO/LDO mapping
  table from CAMF_RES vs CAMS_RES diff for ov02c10/imx681 front driver.

## REA-7 — audiominiext + apoextension
- Payloads are INF/JSON/CAT only (no binaries). Codec = QCOM LPASS internal
  (AUCD VEN_QCOM DEV_0C29, `UseInternalCodec=1`); **no discrete I2C AMP**.
- APO stack: Dolby wrappers + SURFACE_RENDER_MFX per-rev (Colchuck A–D),
  48k/44.1k 2ch float, EQ bypass except notification high-pass, −144 dB
  muted start with ramped transitions.
- Corroborates existing evidence/audio-report.md (D1 idle at 5 s, never D3;
  180 s speaker-protection calibration cycles).
- Linux guidance: keep codec resourced at idle, ramp volume changes.

## REA-5 — SurfaceSerialHubDriver.sys (SAM) — decompiled
- Wire protocol identical to Linux (SSH_SYN 0x55AA, seq frames, CRC-16,
  request-ID skipping zero, ACK-after-2-timeouts) — wire-compatible.
- Real SP11 gaps found: (1) no battery nodes (TC 02) in the SP11
  surface_aggregator_registry group (SP9 5G group has them); (2) no SAM
  sleep/display-on/off/user-presence power integration (Windows pushes
  GUID_CONSOLE_DISPLAY_STATE + GLOBAL_USER_PRESENCE to SAM); (3) HECI/MEI
  fallback transport (Windows USP can ride UART or HECI; Linux UART only).
- Actionable now: add SP11 battery ssam nodes (bat_main/bat_ac pattern from
  the SP9 5G group) — pairs with REA-6's SAM battery-method evidence.
