## 1. QcUsb4Filter8380.sys — the actual host-router HW driver

PE32+ AArch64, ImageBase `0x140000000`, sections `.text` `0x140001000` (0x43d1c),
`.rdata` `0x140045000`, `.data` `0x14004c000`, `PAGE` `0x14005b000`,
`INIT` `0x14007d000`. Lower filter on `USB4\QCOM0CD10001` (INF), below the
in-box Windows USB4 stack.

### 1.1 MMIO discovery — SOSI structure inside the ACPI DSDT (NEW, key finding)

**[observed]** `FUN_140018470` (file `/tmp/rea-usb4-filter-fns/functions/0x140018470.c`):

1. Calls `FUN_14007b8b0(0x41435049 /* "IPCA" */, 0x54445344 /* "DSDT" */, ...)` —
   a wrapper around `ZwQuerySystemInformation(0x4c =
   SystemFirmwareTableInformation)` requesting the **ACPI DSDT firmware table**
   (provider 'IPCA', table 'DSDT'), buffer tagged pool `'qci0'`.
2. `memchr`-scans the first `0x1000` bytes of the DSDT for byte `0x53 ('S')`,
   then compares 4 bytes against `DAT_1400447e8` = `"SOSI\0"` at file offset
   `0x447e8` (confirmed raw bytes `53 4f 53 49`).
3. On match, reads a **64-bit physical address** at `SOSI+5`
   (`uVar8 = *(u64 *)(sosii + 5)` — unaligned physical base of the router MMIO)
   and calls `MmMapIoSpaceEx(uVar8, 0xb8, MmNonCached)` — probes a **0xb8-byte
   header region**.
4. Reads header fields `*(u32 *)(map + 0x9c)` and `*(u32 *)(map + 0xa4)`,
   unmaps, then **re-maps the full region**:
   `MmMapIoSpaceEx(base, (hdr[0xa4/4] + hdr[0x9c/4] + 0x2e) * 4, MmNonCached)`
   → region size = `(word_at_0xa4 + word_at_0x9c + 0x2e) * 4` bytes.

**[derived]** The router MMIO base is not in `_CRS`; it is published as an
embedded `SOSI`-signature structure inside the DSDT AML blob, with the
physical address at `SOSI+5`. For Linux: walk the DSDT for an `SOSI` literal
or take the QCOM0C6D `_CRS`; PR #76's MMIO mapping should size the mapping from
the SOSI header (fields at +0x9c, +0xa4) rather than a fixed size.

### 1.3 Register access path — SOSI-relative indirect window

**[observed]** `FUN_1400182e0` (read reg by index): for index < word[0x27]
(`DAT_140057890`), maps, then copies `word[0x27]*4` bytes from
`base + *(u32 *)(base + 0xa0)` — i.e. **the live register file lives at
`SOSI_base + SOSI[0xa0/4]`**, indices are `u32` slots. Writes in the same
family (`FUN_1400182ec` et al.). **[derived]** All `cio_/lnk_/sb_/cp_/dp_`
code reaches router registers through this indexed window; there is no direct
per-BAR programming. Misalignment and range checks match the strings
"Misaligned CPRIF address", "CPRIF address out of range", "DMEM address out of
range", "PMEM address out of range", "VUIC address out of range",
"Unsupported VUIC access", "Memory range watch point" — CPRIF (router-internal
config-proxy IF), DMEM/PMEM (router processor memories) and VUIC (router IRQ
controller) are all reached via windows validated against SOSI-declared ranges.

## 2. QcUsb4Bus8380.sys — enumeration bus only (no HW)

Re-confirmed with REA analyze (`/tmp/rea-usb4-bus.json`): 1419→994 own
functions; **no `MmMapIoSpace*`, no CPRIF/DMEM/PMEM/VUIC strings, no firmware
strings**. Attaches `ACPI\QCOM0C6D`, enumerates `USB4\QCOM0CD10001` PDOs

thunderbolt/USB4 CM binds the QCOM0C6D-derived device; nothing to port from
the bus driver itself. Prior deep report: `evidence/qcusb4bus-report.md`.

## 3. qcdpps8380 — NOT a DP PHY/clock driver (scope correction)

**[observed]** `/tmp/rea-usb4-qcdpps.json` + strings: `qcdpps.exe` is a
**user-mode Win32 service** (Class SoftwareComponent, `SWC\VEN_QCOM&DEV_0C36`
and `VEN_QCOM&DEV_0D17`), D3DKMT-display client implementing **display LTM
(Local Tone Mapping) + ALS-driven brightness/contrast** for the panel:
`DppsLtmSocketCmdParse::ParseLtm*` (Alpha, Roi, LuxStartPoint, UserControl,
ConstantAls), `DppsAlsSubject` (light-sensor observer), `DppsKmdDriverProbeQDI::
SetLtmHistEvent/SetLtmNoiseThresh`, D3DKMTCreateDevice, CM_Register_Notification
trigger on `ACPI\VEN_QCOM&DEV_0C36` display arrival. Config in
`dppsext/SurfaceLTMConfig.xml` (LTM temporal/backlight/contrast tables, lux
start point 0x190). **No** TCSR/tunnel-clock/PHY register strings at all.
**[derived]** For the SP11 Linux port, qcdpps8380 informs *panel backlight/LTM
policy* (userspace), not `DP_TUNNELING_CLOCK_GEN_EN` or qmp-combo sequencing.
The DP tunnel clock remains: (a) QMP PHY driver (DP_SERDES/clk) + (b) router
sideband handshake from §1.6.

## 5. Actionable mapping to PR #76 blockers

1. **MMIO mapping/alignment**: locate router base via DSDT-embedded `SOSI`
   (signature at DSDT scan, `u64` phys addr at `SOSI+5`); map header (0xb8)
   first, then full region sized `(SOSI_u32@0xa4 + SOSI_u32@0x9c + 0x2e)*4`;
   registers accessed as `u32` index window at `SOSI_base + SOSI_u32@0xa0`.
2. **Firmware loading**: none host-side; router firmware boots autonomously
   (cold/warm). Linux only needs to read the FW version/capabilities from the
   SOSI/CS space and wait for "router ready" (DSR dispatch eligibility).
3. **Stop/restart ownership**: disconnect = PHY standby + SBTX low + SB slot
   reset ("CS/SB registers are reset"); resume = wake FSM → CL0 retrain (HSE
   phases, FOM presets, lane bonding) → SB reconnect → DROM re-validate.
4. DP tunneling clock: no host register toggle found; keep
   DP_TUNNELING_CLOCK_GEN_EN in the QMP/combo PHY domain.
